Operational gaps: the research endpoint has no login and no rate limit, so anyone can spend the LLM/Tavily quota. There's no health endpoint, no structured logs/metrics, no IaC, secrets live only in the Vercel dashboard, and there are no rollback or teardown docs.

Complementary candidate: `civicshieldai-backend` (FastAPI + Postgres + Alembic, sole contributor) for migrations and backup/restore, deferred until confirmed to hold no real client data. Excluded: `kalmus_web` (4 contributors, university SLURM), CampusSwap (user said skip it).

## Constraints
- Budget: $0 target. No paid resource without explicit approval after a priced proposal. Teardown documented for every cloud resource. Budget alerts aren't caps.
- Depth in one cloud. Kubernetes local-only (kind). No new services without a stated problem.
- No invented metrics. Resume bullets get drafted only after a stage is verified.
- Keep secrets, personal data and university/client infrastructure out of public demos.

## Premises (agreed)
1. The research API (long SSE request, 4 external API secrets, cache, cost exposure) is what's worth operating, not the static frontend.
2. One handler runs everywhere through a thin Node adapter. No Express rewrite.
3. Rate limiting before any public URL.
4. GCP Cloud Run is the single cloud. (AWS App Runner closed to new customers 2026-04-30; EB history is unverified, so there's little continuity to keep.)
5. Kubernetes = local kind with the same image. Resume says "local Kubernetes (kind)".
6. No database stage for SpotOn.
7. Load tests never call the LLM provider or Tavily.
8. LLM = Gemini (`gemini-3.5-flash-lite`; `gemini-3.8-flash` measured ~100 s per call plus a 503 on the free tier, 2026-11-01) via Google AI Studio free tier, through a provider-neutral OpenAI-compatible client (`LLM_BASE_URL` / `LLM_API_KEY` / `LLM_MODEL`). Chosen 2026-11-01 over Groq (user preference), OpenRouter `:free` (50 req/day without a $10 purchase), Cerebras ($5 30-day trial, card required), Mistral free (phone verification + training opt-in) and GitHub Models (retired 2026-07-30). Free-tier prompts may be used by Google and seen by human reviewers, so only public song metadata and web snippets go to the model. Implemented on branch `ops/llm-provider`.

## Recommended Approach: staged plan
Each stage lists: build · why · skill · cost · verify · resume evidence.

**Stage 0: Correct the resume entry now ($0).** Use "TypeScript edge/serverless research API" instead of "Node-based". Mark Docker/Actions as an earlier frontend container pipeline. Drop or hedge EB unless you have console screenshots or emails.

**Stage 1: Portable container (FIRST MILESTONE, $0).**
- Build:
  - `server/index.ts`: Node `http` adapter serving `GET /healthz`, `/api/research-song` (calls the existing handler with a web `Request`, streams the `Response` body), and `dist/` with SPA fallback. Bundled with the already-installed `rolldown`, so no new dependency.
  - Fix the hardcoded redirect URI to `${location.origin}/callback`, so one image works on any host.
  - Multi-stage `Dockerfile`: pinned `node:24-alpine`, `npm ci`, build, prod-only deps, `USER node`, `HEALTHCHECK`, `PORT` env, runs with a read-only root filesystem.
  - `.dockerignore` (keeps `.env` out).
  - `compose.yaml`: app + `redis:7-alpine` + `hiett/serverless-redis-http`, so the unchanged Upstash client talks to a real local Redis.
- Why: the backend has never run anywhere but Vercel. This makes it portable for Stages 4 and 6.
- Skill: multi-stage builds, non-root containers, health checks, build-time vs. runtime config, container networking.
- Verify: `docker compose up`; `curl /healthz`; a cached-report SSE stream via curl; `docker inspect` shows a non-root user; container runs with `--read-only`; image size recorded; adapter has vitest coverage.
- Evidence: Dockerfile, compose file, measured image size, test output.

**Stage 2: Abuse and cost protection ($0).**
- Build:
  - Fixed-window rate limit per client IP using the existing Upstash client (`INCR`/`EXPIRE`). Cache hits are free; uncached runs are limited per IP plus a **global daily cap**.
  - If Redis is down, uncached runs are refused (fail closed, protects money); cache reads stay fail-open.
  - Input length validation.
- Why: closes the open spend hole on Vercel too, since the handler is shared.
- Skill: rate-limit design, trusting proxy headers (`X-Forwarded-For` can be spoofed, which is why the global cap is the real money guard), fail-open vs. fail-closed.
- Verify: unit tests; a curl loop shows 429 after N; with Redis stopped, uncached runs are refused.
- Evidence: tests and a documented limit policy.

**Stage 3: CI image pipeline ($0).**
- Build:
  - PRs: build the image, Trivy scan (fail on CRITICAL), boot it and smoke-test `/healthz`.
  - master: push to GHCR tagged with the git SHA (no `:latest`), using only `GITHUB_TOKEN` with `packages: write` scoped to that job.
- Why: replaces the old long-lived Docker Hub token.
- Skill: CI supply chain, least-privilege job permissions, immutable tags.
- Verify: green runs; a deliberately broken healthcheck fails CI.
- Evidence: workflow runs and the GHCR package page.

**Stage 4: Cloud Run with Terraform (needs approval; ~$0 idle).**
- Build: `infra/terraform/` with:
  - enabled APIs;
  - an Artifact Registry repo with a cleanup policy;
  - a runtime service account with `secretAccessor` on its 5 secrets only;
  - a deployer service account (`run.developer`, AR writer, `actAs` on the runtime SA only);
  - a Workload Identity pool and provider limited to `assertion.repository == "minhpham1810/SpotOn"` on master;
  - a `cloud_run_v2_service` (min 0, max 2, timeout 300 s, probes on `/healthz`; image changes ignored by Terraform because CI owns deploys);
  - a billing budget with email alerts.

  Secret **values** are added out-of-band (`gcloud secrets versions add`) so they never land in Terraform state.

  The CI deploy job: OIDC auth → push → `gcloud run deploy --image …@sha256` → smoke test → on failure, shift traffic back to the previous revision.

  `scripts/teardown.sh`: `terraform destroy`, then list any leftover Cloud Run, AR, secrets and buckets.

  Manual: add the `*.run.app/callback` redirect URI in Spotify's dashboard.
- Why: HTTPS, identity, secrets and deploys you own and can explain.
- Skill: IaC, IAM least privilege, short-lived CI credentials (OIDC), secret management, revisions and rollback.
- Verify: `terraform plan` is clean after apply; CI deploy has no JSON keys; a bad image gets rolled back; teardown leaves nothing billable (listed).
- Evidence: Terraform code, workflow logs, rollback drill notes, billing report showing $0.

**Stage 5: Observability (check pricing first).**
- Build:
  - One JSON log line per request: `trackId`, cache hit, rounds, duration, outcome, rate-limited.
  - Log-based metrics.
  - Email alerts on error ratio, rate-limit spikes, and daily uncached runs near the cap.
  - An uptime check on `/healthz`.
- Skill: structured logging, metrics from logs, actionable alerts.
- Verify: drills. Revoke the Gemini key → the error alert fires; spam requests → the 429 alert fires.
- Evidence: alert screenshots with timestamps and the drill log.

**Stage 6: Local Kubernetes on kind ($0).**
- Build: plain YAML in `k8s/`:
  - an app Deployment (2 replicas) and Service;
  - a ConfigMap;
  - a Secret created from local `.env` and never committed;
  - Redis + SRH;
  - readiness/liveness probes. Readiness must **not** depend on Redis, because cache use is optional;
  - requests/limits;
  - rolling updates via `kind load docker-image`.
- Drills: missing secret → CrashLoopBackOff; memory limit too low → OOMKilled; wrong tag → ImagePullBackOff; failing readiness → no endpoints; SSE through port-forward.
- Skill: core Kubernetes objects and `kubectl describe/logs/events` debugging.
- Evidence: manifests and the drill write-ups. Label it "local (kind)".

**Stage 7: Repeatable load tests ($0).**
- Build:
  - `LLM_BASE_URL` (already implemented) pointed at a small mock that streams a canned final answer after a set delay, so no tool calls happen and Gemini/Tavily/Genius are never hit. Spotify audio features fail into the existing fallback.
  - k6 scripts for (a) the cache-hit path and (b) concurrent long-lived SSE streams per instance at a fixed CPU limit.
- Verify: record machine, versions, limits and concurrency in `bench/load/README.md`.
- Evidence: the measured numbers only, with their conditions.

**Stage 8: Docs and resume.** `docs/ops/`: architecture, setup, runbook (deploy, rollback, rotate a secret, teardown, cost check), demo script. Resume bullets get drafted from verified stage evidence only.
